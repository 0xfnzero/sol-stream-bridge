# React 管理面板

[English](DASHBOARD.md) · [共享订阅](SHARED_CN.md) · [项目首页](../README_CN.md)

本功能已包含在 **v0.2.0 Linux 安装包中**。面板运行在共享 Yellowstone 接收端 B，用于管理 Bot 用户和查看转发状态。前端使用 React + TypeScript，Rust 进程同时提供静态页面和管理 API，无需独立 Web 服务。

## 能管理什么

- 真实运行状态：上游连接、下游 TCP 连接、活动订阅、用户用量、合并过滤器/账户数、消息分发速率、拒绝请求、慢客户端和上游中断。
- 用户：创建随机 API Key、设置订阅/过滤器/账户累计额度、允许或禁止账户更新、停用、启用、轮换 Key、删除。
- 订阅：查看来源 IP、订阅时间、已入队分发消息数，断开指定 Subscribe 流。列表最多显示 200 条；停用用户可断开该用户全部订阅。
- 访问策略：IP 白名单和独立的“要求用户 API Key”开关。开启时必须同时通过 Key 和 IP 检查；关闭时按来源 IP 分配用户额度。

Shred 路由、默认透传模式、监听地址、TLS、供应商凭证及全局上游额度仍由 TOML 管理。面板管理的是共享 gRPC 接收端，并非所有转发方式的通用配置编辑器。计数与速率反映接收/入队消息，不是网络吞吐字节、Bot 已处理确认或端到端延迟测量；历史曲线仅保存在当前页面内存。

## 安装与启动

先完成 [共享模式部署](SHARED_CN.md)，确保源 A 与接收端 B 的隧道配置一致。使用 `VERSION=v0.2.0 ROLE=shared-receiver ./install.sh` 安装 B，然后在安装目录执行以下命令；源码部署也在仓库目录执行：

```bash
# 源码构建页面需要 Node.js >=22.12、npm；生成凭据需要 openssl
./setup-dashboard.sh
```

源码目录每次运行脚本都会重新构建页面；`git pull` 升级后应重跑，确保登录页与服务端匹配。预编译 Release 安装包直接使用自带资源，无需 Node.js。

脚本在页面构建成功后生成短随机账号（`sb_` 加 6 位十六进制字符，共 9 位）和随机初始密码，**仅在首次成功初始化的终端输出一次**。同时保存为权限 `600` 的 `.dashboard-initial-credentials`：第一行账号，第二行初始密码。重复执行会保留已有凭据，不再打印密码。登录页不会公开初始凭据；显隐按钮仅用于查看自己输入的密码。

如需自定义初始账号，可在首次初始化时执行 `DASHBOARD_INITIAL_USERNAME=my_bridge ./setup-dashboard.sh`。账号允许 3–64 位英文字母、数字、点、下划线或连字符，禁止使用 `admin`、`administrator`、`root`。将下表添加到实际使用的共享接收端配置中（不要重复添加）：

```toml
[grpc.shared.dashboard]
listen = "127.0.0.1:8080"
auth_file = "dashboard-admin.toml"
# 可选：自定义初始凭据的环境变量名称
# initial_username_env = "DASHBOARD_INITIAL_USERNAME"
# initial_password_env = "DASHBOARD_INITIAL_PASSWORD"
state_file = "dashboard-state.toml"
assets_dir = "dashboard/dist"
```

`config.shared-receiver.toml` 已提供注释模板。新安装也可用 `./setup.sh shared-receiver` 创建配置和隧道凭证；已有 `config.toml` 会保留，不会自动切换模式。编辑 `api_keys`、白名单、上游和隧道设置后检查并启动：

```bash
cargo build --release --locked # 仅源码部署；预编译安装包跳过此行
./run.sh config.shared-receiver.toml --check
./run.sh config.shared-receiver.toml
```

**预编译安装包使用安装根目录的 `config.toml`**，运行 `./run.sh --check` 和 `./run.sh`，省略上述文件参数；模板位于 `configs/`。源码部署使用 `config.toml` 时也省略文件参数。`run.sh` 将凭据文件的两行作为数据读入 `DASHBOARD_INITIAL_USERNAME` 和 `DASHBOARD_INITIAL_PASSWORD`，已导出的同名变量优先。自定义上述环境变量名称时需自行导出对应变量。直接运行二进制时，首次启动也要提供这些变量，并从项目/安装目录运行，因为配置路径相对于工作目录。`--check` 只验证，不创建账号。

访问 [http://127.0.0.1:8080](http://127.0.0.1:8080)，输入初始账号密码，**首次登录必须修改密码后才能进入控制台**。新密码至少 12 个字符、最多 128 个 UTF-8 字节，不允许控制字符。以后点击控制台顶部的钥匙按钮修改密码，需要输入当前密码并确认新密码。修改成功会撤销所有面板登录会话，要求重新登录；Bot 用户的 API Key 和转发连接不受影响。

实际首次启动会将 Argon2id 密码哈希保存到 `dashboard-admin.toml`（权限 `600`、原子写入、进程独占锁）。该文件存在后，初始环境变量不再参与认证。完成首次改密后可删除 `.dashboard-initial-credentials`，它不是当前密码存储文件。凭据文件损坏或权限不安全时会拒绝启动，不自动重置账号。

v0.2.0 Linux 安装包包含构建好的 `dashboard/dist` 和初始化脚本，运行无需 Node.js。已有 v0.1.1 部署需先升级二进制，再启用共享模式和管理面板。

## 远程管理

面板强制监听 loopback，不开放到公网或局域网。通过 SSH 转发访问：

```bash
ssh -N -L 8080:127.0.0.1:8080 user@RECEIVER_IP
```

在本地浏览器打开 `http://127.0.0.1:8080`。若本地端口已占用，可改用 `-L 18080:127.0.0.1:8080` 和 `http://127.0.0.1:18080`。管理 HTTP 走 SSH 通道，不改变 Bot、上游或桥接隧道的传输设置。Host 仅接受 localhost/127.0.0.1/::1，跨来源浏览器请求会被拒绝。

面板账号与用户 API Key、`BRIDGE_TOKEN`、供应商 `x-token` **互相独立**。登录后产生随机会话令牌，仅放在浏览器内存，不写入 localStorage、Cookie 或 URL；服务端仅保留令牌哈希。会话最长有效 8 小时，刷新需重新登录，退出会撤销当前会话，服务重启会清空所有会话。修改密码立即撤销全部会话，无需重启。登录与改密共享每分钟 10 次的全局请求限制，同时最多执行一个密码哈希任务，仅保留最近 32 个会话，超过时成功登录会撤销最早的会话。

## 迁移与账号恢复

若使用过早期 main 分支的 `DASHBOARD_TOKEN` 登录，执行初始化脚本，将**仅 `[grpc.shared.dashboard]` 下的 `token_env`** 替换为上面的 `auth_file` 配置。旧管理员令牌不再用于登录；保留 `dashboard-state.toml` 和桥接、供应商的 Token 配置。

忘记密码时，先停止服务，安全备份并移走配置指向的 `auth_file` 和 `.dashboard-initial-credentials`，重新执行初始化脚本并启动，即可创建需要首次改密的新账号。保留 `dashboard-state.toml`，避免重置 Bot 用户密钥与策略。恢复后妥善保护或安全清理旧凭据备份。单纯修改初始环境变量不会重置已有账号。

## 用户与生效规则

1. 添加用户并设置额度。新 Key 只在创建或轮换成功后显示一次，关闭后无法再次查询；丢失时轮换。
2. 如果界面提示 Key 验证未开启，前往访问策略显式开启。添加用户本身不会改变全局验证方式。已有 Key 非空的 TOML 初始配置默认开启。
3. 将 Key 交给相应 Bot，使用 v0.2.0 客户端的 `api_key` 参数，或 Yellowstone 的 `x-token` / `x-api-key` metadata。不要把面板账号密码或会话令牌交给 Bot。
4. 每用户额度在该用户所有订阅间累计，另受每流与全局上游额度限制。允许账户更新是单用户明确授权。

每项额度和账户更新权限均支持**跟随服务默认**或自定义。新用户默认继承，编辑时会保留原来的选择。继承时分别保留单条与累计限制，例如单条 8 个过滤器、用户累计 16 个；自定义过滤器/账户额度同时用于单条和该用户累计限制。在表单中来回切换继承开关，会保留尚未保存的自定义输入。

修改用户 Key/额度/状态、删除用户会终止该用户现有订阅；其他用户保留。移除 IP 会终止来自该 IP 的订阅。切换全局 Key 验证会终止全部订阅。Bot 需要处理流结束并重新订阅。手动断开仅关闭指定流，用户仍可重新连接；需禁止重连时停用用户或移除 IP。TCP 连接可能保持 HTTP/2 空闲状态，因此 TCP 数不会因关闭 Subscribe 立即归零。

删除/停用最后一个 Key **不会关闭认证**，此时没有用户可以凭 Key 进入。IP 白名单为空则拒绝所有 gRPC 客户端。Key 验证关闭时，身份为 `ip:<来源IP>`，命名 Key 用户的额度不用于匿名 IP；已有 TOML 的 `grpc.shared.users."ip:..."` 配额可在面板编辑，不应向这类身份分配用户 Key。

## 持久化与备份

首次启动时从 TOML 的 `grpc.api_keys`、`grpc.allowed_sources`、`grpc.shared.users` 初始化。第一次成功保存管理修改后，`dashboard-state.toml` 成为这三类设置的权威来源，重启后仍然生效；原 TOML 不被改写。其他字段继续使用 TOML。

状态文件含用户明文 Key，必须是普通文件且 Unix 权限不向组或其他用户开放（推荐 `chmod 600 dashboard-state.toml`）。进程以原子替换方式保存；多个服务不能写同一状态文件。外部修改、文件损坏、权限不安全会导致拒绝保存或启动失败，不会自动回退到旧 Key。管理 API 查询不会返回这些密钥。

备份 `dashboard-state.toml`、`dashboard-admin.toml`、实际配置、仍保留的 `.dashboard-initial-credentials`、`.bridge-token` 和隧道凭证，限制备份访问权限。安装升级会保留根目录 TOML、凭据文件和证书，也保留旧 `.dashboard-token`；自定义外部路径由运维自行备份。不要删除状态文件来“重置界面”：删除后重启会重新启用 TOML 中的旧用户/Key。停用面板或切回旧二进制同样需先核对 TOML 策略。

保存会校验页面看到的配置版本。多管理员同时编辑时，过时修改返回 409，用户表单可点击“载入最新配置”明确替换草稿，访问策略重新载入后再提交；不会默默覆盖其他管理员修改。请求中断或超时时保存可能已经完成，先刷新状态再决定是否重试。新建/轮换响应丢失时，可再次轮换生成一个已知 Key。

状态文件已持久化后，保存完全相同的用户设置或访问策略不会重写文件、递增版本或中断订阅，但仍校验版本和文件完整性。第一次成功保存即使与 TOML 相同，也会建立持久化状态。关闭用户表单、离开访问策略页或退出登录时，会确认是否丢弃草稿；有未保存修改时，刷新或关闭浏览器标签页也会在浏览器允许的情况下触发提醒。

## 开发验证

```bash
cd dashboard
npm ci
npm run build
npm test
# 开发页面：127.0.0.1:5173，API 代理到已运行的 Rust 面板 127.0.0.1:8080
npm run dev
```

前端没有转发热路径逻辑；可见时每 2 秒读取状态，后台标签页暂停轮询，返回时立即同步。并发刷新共用请求，保存后主动获取新状态，过时响应不会覆盖新数据。登录过期自动返回登录页。用户列表每页 25 行，搜索覆盖全部用户；一次性 Key 弹窗需要明确确认才能关闭。文件持久化和密码哈希在后台阻塞任务进行，不在转发锁内执行。默认不开启面板时，不加载静态页面、不启动管理监听。没有进行生产流量延迟基准测试。
